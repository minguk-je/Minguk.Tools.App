# 몹 검출 · 라벨링 · 학습 · 글자 읽기

화면에서 몹을 **찾는다**(사각형 + 이름). 분류가 아니다 - 자동화하려면 좌표가 있어야 한다.
CLAUDE.md 에서 떼어 온 자세한 규칙과 실측이다. 학습 절차는 `docs/ONNX-모델-학습.md`, 속도 설계는 `docs/몹-찾기-속도-설계.md`.

```
화면캡처 ──담기(F8)──▶ 프로젝트 폴더(Images·Labels) ──라벨링──▶ 학습(YOLO11n/D-FINE-N, 파이썬) ──▶ detector.onnx ──▶ 스크립트·플레이의 몹 찾기
```

## 라벨 형식 - YOLO 그대로

```
<프로젝트 폴더>/
  Images/  Labels/(그림과 같은 이름 .txt)  classes.txt(한 줄에 몹 하나)  class-colors.json  regions.json
  detector.onnx  detector.json  detector.<이름>.onnx(보관본)
```

한 줄 = `<몹 번호> <가운데 x> <가운데 y> <너비> <높이>`, 좌표는 모두 **0~1**.

- 소수점은 `InvariantCulture` 로 쓰고 읽는다 - 유럽 지역 PC 에서 `0,5` 가 되면 칸 수부터 달라진다(`de-DE` 로 바꿔 놓고 검사한다).
- 사각형은 파일과 같은 자릿수(6)로 반올림한다(`LabelBox.Digits`) - 안 그러면 되읽은 사각형이 `==` 로 달라 "고른 사각형" 을 못 찾는다.
- 라벨을 다 지우면 파일도 지운다 - 빈 파일은 "배경 사진" 으로 배운다.
- **몹은 아무 라벨에도 안 쓰인 것만 지운다**(`LabelDataset.RemoveClass`). 라벨에는 번호가 들어 있어 중간을 지우면 뒤가 조용히 다른 몹을 가리킨다.
  지울 때 뒤 번호의 라벨 파일·색을 같이 당기고, 쓰인 몹은 어느 파일에 쓰였는지 말하고 거절한다(`FindLabelsUsing`). 이름 바꾸기는 안전하다.
- 몹 색: 번호에서 만든 기본 색(황금각, `LabelPalette.DefaultColor`), 사람이 고른 것만 `class-colors.json`(번호 순, 안 고른 자리 null). classes.txt 는 YOLO 형식이라 안 넣는다.

## 모델 - ONNX Runtime (DirectML)

지금 쓰는 모델은 **YOLO11n**(평소) 과 **D-FINE-N**(비교용) 이다. 둘 다 파이썬으로 학습해 ONNX 로 들인다.

| 98장 · GTX 1060 3GB | 학습 | 재현율 | 추론 한 장 |
|---|---|---|---|
| YOLO11n | 5분 | 194/194 | 10.9 ms |
| YOLO11s | 10분 | 194/194 | 23.5 ms |
| D-FINE-N | 1시간 45분 | 191/192 · 헛것 0 | 28~32 ms |
| (옛) TorchSharp AutoFormerV2 640x360 | 46분 | 135/192 · 헛것 5 | 606 ms + libtorch 4.3GB |

- **모델 정책(사용자)**: 포트폴리오용이라 남에게 넘기지 않는다 - YOLO11n 을 평소에 써도 된다. YOLO(Ultralytics)는 AGPL-3.0 이라 의무는 넘길 때 생긴다.
  GitHub 에 올릴 때만 짚는다(학습한 YOLO 모델을 저장소에 넣으면 저장소를 AGPL 로, DevExpress 키·DLL 은 올리지 않는다).
- **라벨링 화면 "쓰는 모델" 콤보**: 목록은 보관본 `detector.<이름>.onnx`. 고르면 `DetectorFiles.Use` 가 보관본·쪽지를 `detector.onnx` 자리에 복사하고 시각을 찍는다 -
  켜 둔 스크립트·플레이 화면이 몇 초 안에 따라온다. 보관본은 지우지 않는다.
- **쪽지(detector.json)**: 모델 이름(`modelName`)·크기·**넣는 법(`letterbox`)**·장수·바퀴·재현율. D-FINE·RT-DETR 은 **늘리기**, YOLO 는 **비율**(여백).
  크기가 맞아도 넣는 법이 다르면 한 마리도 못 찾는다. 크기·넣는 법은 설정이 아니라 **모델과 함께** 남긴다 - 설정에서 읽으면 옛 모델의 좌표가 조용히 어긋난다.
- **DirectML 은 `MatMul(행렬, 1차원 벡터)` 를 틀리게 계산한다**(onnxruntime-directml 1.24.4 / DirectML 1.15.4) - 벡터를 무시하고 행 합계를 준다.
  D-FINE 디코더에 세 군데 있어 **터지지도 느려지지도 않고 답만 틀린다**(점수 0.9 → 0.06, 헛것도 0 이라 "덜 배웠나" 로 보인다).
  고치기 `python 도구/onnx-DirectML-고치기.py <onnx>`. `--import-onnx` 가 들이기 전에 GPU·CPU 답을 견줘 막는다(`--그래도`). YOLO 는 해당 없음.
- 혼자 보기: `--onnx-agree --model= --image=` · `--onnx-raw --model= --image= [--cpu]` · `--onnx-bench --model= [--size=]` · `--onnx-detect`(결과 그림은 임시 폴더).
- `--import-onnx --model= --size=640x640 --fit=늘리기|비율 --name=` - `--root=` 가 없으면 앱이 쓰는 `detector.onnx` 를 **덮는다**. 시험할 때는 꼭 준다.

## 학습 - 파이썬, 앱 밖 폴더

- **자리 둘**: **학습 경로** `Vision.TrainingRoot`(도구 - `yolo-venv`·`dfine-venv`·`D-FINE` 저장소·`dfine_n_coco.pth`·`runs`, 지워도 `도구\학습-환경-준비.ps1` 로 다시 만든다)
  와 **작업공간** `Vision.ProjectsRoot`(내 것 - 솔루션·사진·라벨·모델, 다시 못 만든다 - 백업할 곳). 둘 다 환경설정 화면에서 고른다.
  기본은 설치 루트 아래(`InstallPaths`, 실행 폴더가 아니다 - Velopack 이 업데이트 때 `current` 를 갈아 끼운다).
- 앱은 파이썬 환경을 받지 않는다 - 없으면 무엇이 없는지 적고 스크립트를 가리킨다. **가상환경은 복사해 못 옮긴다**(pyvenv.cfg 에 그 PC 경로).
- **라벨링 화면 학습 버튼은 콤보에 고른 모델로 학습한다.**
  - YOLO: `YoloTrainer` 가 `yolo-venv` 로 `Tools\yolo-학습.py`(csproj 가 `도구\` 에서 복사)를 띄워 바퀴마다 진행·box loss 를 읽고, 끝나면 ONNX 를 들여 보관본을 갈고 재현율을 잰다.
    진행 줄 앞의 `ESC[K` 는 떼고 읽는다. 멈추기는 프로세스 트리를 끈다.
    스크립트는 묶음마다 `BATCH <바퀴> <바퀴 수> <묶음> <묶음 수> <loss>`, 바퀴마다 `PREVIEW <runs\yolo11n\학습-묶음.jpg>` 를 찍는다(`report_progress`, 2026-09-15).
    `BATCH` 는 진행 막대 조각 뒤에 붙어 온다(실측 `0/13 0.3sBATCH 9 20 1 13 1.37`) - 줄 머리가 아니라 줄 안에서 찾는다. 묶음 그림은 `on_train_batch_end` 에 안 와서
    `preprocess_batch` 를 감싸 붙들고, `plot_images(save=False, threaded=False)` 로 그려 임시 파일 → `os.replace`(`plots=True` 는 결과 그래프까지 그려 느리다).
    상자 색은 몹 색(`--colors RRGGBB,…` → `plotting.colors.palette` 갈아 끼우기).
  - **학습 크기**(YOLO, `--imgsz`, 라벨링 화면 `학습 크기` 480·640·960·1280, 설정 `YoloImageSize`, 2026-09-15) - 작은 몹을 잘 찾게. 학습·내보내기·쪽지(`ImportOnnx`) 모두 그 크기,
    몹 찾기는 ONNX 에 박힌 입력 크기를 읽어(`OnnxDetector`) 따로 고칠 것이 없다. 묶음 수는 640 기준(n 8·그 밖 4)에서 픽셀 수에 반비례(`BatchFor`: n 960→4 · 1280→2).
    실측: 16장 1280 2바퀴 30초, 쪽지·ONNX 입력 1280x1280(`--yolo-train --imgsz=1280`). D-FINE 은 640 고정.
  - D-FINE: `DFineTrainer` 가 COCO 로 내보내고(`DatasetExport.WriteCoco`) `mob_detection.yml` 을 다시 써서 `train.py` → `export_onnx.py` → DirectML 고치기 → 늘리기로 들인다.
  - `--yolo-train --root=<시험 폴더> [--epochs=2] [--imgsz=640]` 가 화면 없이 같은 길을 돈다(묶음 진행·묶음 그림·학습 크기까지 본다) - 들이기까지 하므로 앱 폴더에는 안 돌린다.
- 한 방 명령 `.\도구\yolo-학습.ps1`(앱을 닫고) - 환경 → 학습·내보내기 → 하네스 빌드 → 들이기 → 재현율 → 속도. 98장 약 7분. PowerShell 5.1 용(삼항 없음, UTF-8 BOM).
- **학습 뒤에는 재현율을 본다**(`--detect-check`, IoU 0.5, `DetectionMatch` 한 벌) - "끝났습니다" 는 모델이 만들어졌다는 뜻이지 찾는다는 뜻이 아니다. 학습에 쓴 그림이라 외운 것도 맞은 것이다.
- 하네스도 `UserDataPaths.Initialize()` 를 먼저 부른다 - 안 부르면 두 경로가 기본값으로 떨어져 "모델이 없다" 가 된다.
- 시험은 솔루션 탭 `새 프로젝트` 로 시험용 프로젝트를 따로 만들어 한다. 씨앗 심는 스크립트는 `Images/`·`Labels/` 를 비운다.

### TorchSharp(옛 길) - 하네스·대체 경로에만 남았다

화면에서는 뺐다("안 쓰는 건 없애줘"). `DetectorTrainer`·`LibTorchRuntime` 은 `--train-check`·`--detect-bench` 와 ONNX 가 없을 때의 대체 경로가 쓴다. 다시 쓸 일이 있으면 기억할 것만:
- TorchSharp 0.102.7 ↔ libtorch 2.2.1 짝, libtorch 는 NuGet 이 아니라 pytorch.org zip 을 받아 `NativeLibrary.Load` 로 `torch_cpu`·`torch` 를 먼저 올린다(출력 3.6GB 를 피하려고).
- ONNX 로 못 내보낸다. CPU 학습은 29배 느려 못 쓴다. 기본 학습률 1.0 은 실제 화면을 못 배운다(0.1). 크기는 파이프라인 안에서 `ResizeImages`(Fill).
- GPU 고르기: `CUDA_VISIBLE_DEVICES`·`CUDA_DEVICE_ORDER=PCI_BUS_ID` 를 `_putenv_s` 로(C 런타임 표), 자동은 모니터 안 붙은 카드·사용률 낮은 카드. 스레드 `set_num_threads(코어/4)`, `KMP_BLOCKTIME=0`.

## 실시간 몹 찾기 (스크립트·플레이 화면)

- **0.08초에 한 번**(`DetectIntervalMs`), 앞 것이 돌고 있으면 그 프레임은 흘린다 - 실시간에서 늦은 답은 틀린 답이다. 더 빠르게 붙이려면 캡처 fps 를 같이 올린다.
- 캡처 스레드에서 기다리지 않는다 - 줄여서 떨어뜨리고 추론은 백그라운드. 임시 PNG 는 모델 입력 크기 이상으로 만든다(작게 만들면 작은 봇을 놓친다), 프로세스마다 이름을 나누고 켤 때 옛것을 치운다.
- 켤 때 CPU 리드백이 꺼져 있으면 알아서 켜고 적는다(`EnsureCpuReadback` - 리드백은 세션을 만들 때 정해져 **껐다 켜는 것이 유일한 길**). 프레임 저장·담기도 같다.
- 모델을 못 읽거나 추론이 터지면 토글을 끈다 - **먼저 끄고 나서 이유를 적는다**(끄는 콜백이 안내를 지운다). 긴 안내는 도구 줄이 아니라 상태 줄에.
- **다시 학습·모델을 바꾸면 알아서 읽는다**(5초마다 파일 시각·경로 비교, 같은 시각이 2초 유지된 뒤 - 쓰는 도중에 읽지 않는다).
- **추적**(`DetectionTracker`, 기본 켬): IoU 0.3 으로 잇고, 두 번 연속 보인 것만 내놓고, 두 번까지 놓쳐도 잇는다. 겹침이 0 이어도 가운데가 크기의 1.5배 안이면 같은 몹.
  누르기·자동 라벨도 추적 결과를 쓴다. 한 프레임짜리 헛것 대책은 `목표()` 에 있다(`docs/실시간-스크립트.md`).
- 겹그림 `Markup/DetectionOverlay` - 그림은 안 그리고 마우스는 통과시킨다(미리보기가 클릭을 게임으로 넘긴다). 점선 = 모델, 실선 = 사람.
- **담기 F8** 은 전역 단축키 + 소리(담김·거절). 결과는 아래 바에 "N장째". 몹 찾기가 켜진 채 담으면 찾은 것을 라벨로 같이 쓴다(`FreshDetections`, 없으면 라벨 파일을 안 만든다).
- **누르기**는 입력 전달이 켜져 있을 때만 나간다 - 찾기만 켰다고 클릭이 나가면 안 된다. 손으로 누를 때와 같은 길(`SendClickAsync`·`MapRatioToScreen`).

## 글자 읽기 (OCR)

`Windows.Media.Ocr`(`IOcrEngine`·`WindowsOcrEngine`·`OcrEngineFactory`). 받을 것이 없다. 언어 팩이 없으면 팩터리가 추가하라고 말한다.

- 영역을 정해서 읽는다. 작은 글자는 키워서(높이 160 아래면 최대 4배). **글자가 그림 가장자리에 닿으면 빈 글** - 자리는 넉넉하게.
- **몹 이름표**: 검출 사각형 위를 잘라(`NameplateRegion.Above`) 빨간 픽셀만 남기고 3배(`NameplateInk`), **ko 엔진**. 원본 프레임이 필요해 검출마다 한 벌 복사.
- **HUD 숫자**: 흰 글자만 남겨(`HudInk`) **en-US 엔진** - ko 는 숫자를 망친다(225 → `22512h5`). 전처리 여부는 자리마다(`HudSpot.Ink`), 빈 답이면 다른 길로 한 번 더.
  오버워치 HUD 는 영웅이 달라도 같은 비율 자리다.
- **이름 붙인 자리**(`NamedRegion`·`RegionBook`, 프로젝트 폴더 `regions.json`): 스크립트는 `읽기("이름")`·`숫자읽기("이름")`·`글자있나("이름")` 로 부른다. 이름은 대소문자를 안 가린다.
  - 만드는 곳은 스크립트 화면 - 이름을 먼저 적고 `영역 지정` 을 켠 뒤 끈다(끌고 나서 묻는 창은 게임을 가린다). `지금 읽기` 로 곧바로 맞춘다.
  - 켜 둔 동안 미리보기가 편집기다: 빈 자리 끌기 = 새 자리, 안쪽 = 옮기기, 손잡이 = 크기(원본 픽셀로 뜬다), 휠 = 확대, 오른쪽 끌기 = 옮기기.
    `Markup/Regions`(`RegionCanvas`·`RegionResizeAdorner`·`RegionGeometry`) - 클릭이 게임으로 새지 않는 것은 `IsEditing` 이 지킨다. 휠은 `PreviewMouseWheel`(ScrollViewer 가 버블을 먹는다).
  - `글자 영역` 과 끌기 손짓을 나눠 쓴다 - 한쪽을 켜면 다른 쪽을 끈다.
- 도구: `--ocr-crop --image= --region=x,y,w,h [--ink] [--lang=] [--scale=]`(오려낸 조각을 남긴다) · `--nameplate-check`.

## 라벨링 화면

- 데이터셋 자리 = 솔루션 탭에서 고른 프로젝트(`LabelDataset.ConfiguredRoot`). 폴더 고르기는 없다 - 위 칸과 어긋나지 않게.
- 그림을 넘길 때 자동 저장. 캔버스(`Markup/LabelCanvas`)가 그림과 사각형을 직접 그린다 - 좌표 변환은 `ToScreen`·`ToNormalized` 둘뿐. 확대도 캔버스 안(`Zoom`, 그림 자리에만 배율).
- 사각형 편집 계산은 `LabelBoxEdit`(순수). 손잡이는 고른 것에서만, 옮기기는 시작 사각형 + 변위(4px 안 떨림은 무시), 화살표 1px · Shift 10px.
  손 덜 타기: `앞 장 가져오기` · `점선 받기` · 담을 때 자동 라벨.
- 뼈대: 도구 줄 / `DockLayoutManager`(그림 | 라벨 | 몹, 아래 학습 패널, 끌기·띄우기·닫기 막음) / 상태 줄.
  - 학습 칸 `학습 묶음 보기`(`ShowTrainingBatch`, 저장) - 켜면 학습하는 동안 라벨 판 자리에 바퀴마다 바뀌는 학습 묶음 그림을 덮는다(끝나거나 끄면 라벨 판).

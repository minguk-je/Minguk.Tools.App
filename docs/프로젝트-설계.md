# 프로젝트 설계 — 솔루션과 프로젝트

게임 하나에 딸린 것(사진·라벨·모델·영역·스크립트)을 **솔루션 / 프로젝트** 두 겹으로 묶는다.
구조·용어·조작은 **Visual Studio 2026** 을 따른다. (2026-09-14 정하고 만들었다 - 이 문서는 지금 모양이다.)

## 왜 두 겹인가

- **한 게임 안에서도 모드마다 검출이 다르다.** 오버워치 사격장은 "일반봇" 한 종인데 6:6 은 영웅 21종이다. RPG 는 사냥터마다 검출이 통째로 바뀐다.
  모델을 하나로 두면 클래스가 수백이 되고, 사냥터 하나 늘 때마다 전체를 다시 학습해야 한다. 그래서 모델·사진은 프로젝트마다.
- 속도는 갈림길이 아니다 - YOLO·D-FINE 은 출력이 `4+검출수` 라 검출 수와 추론 시간이 거의 무관하다. 갈리는 것은 정확도와 학습 시간이다.
- **프로젝트 단위는 "맵" 이 아니라 "런"** - 걸어가면 맵이 안 끊기는 게임에서 맵마다 나누면 사람이 계속 바꿔 줘야 한다. 한 번 누르면 끝까지 도는 덩어리(안달리엘런·카우방)가 한 프로젝트다.
- **사진도 프로젝트마다** - 같은 검출이라도 스테이지마다 배경·조명이 달라 사진이 다르다. 겹치는 것은 `classes.txt` 한 줄뿐. "프로젝트를 고르면 전부 교체" 라는 예외 없는 규칙을 얻는다.

## 폴더

```
<작업공간>\                         ← 환경설정에서 정한다(Vision.ProjectsRoot). 솔루션 폴더의 위다
└─ 디아2\                           ← 솔루션 폴더 (= 게임)
   ├─ 디아2.mtsln
   ├─ settings.form.json  settings.values.json   ← 솔루션 공통 설정(docs/솔루션-설정.md)
   ├─ 공용\                         ← 공유 프로젝트 (VS 의 .shproj) - 시작 파일 없음
   │  ├─ 공용.mtsproj
   │  └─ 공용.csx …
   ├─ 안달리엘런\                   ← 프로젝트 (= 런)
   │  ├─ 안달리엘런.mtsproj         ← 공용 을 ProjectReference 로 문다
   │  ├─ main.csx  Resources\
   │  ├─ bin\안달리엘런.mtsx        ← 빌드한 완성품 (+ Resources\, 바깥 DLL)
   │  ├─ Images\  Labels\  classes.txt  class-colors.json  regions.json
   │  ├─ Captures\                  ← 프레임 저장
   │  ├─ Recordings\                ← 화면캡처 녹화(mp4)
   │  ├─ settings.form.json  settings.values.json   ← 이 런의 설정
   │  └─ detector.onnx  detector.json  detector.<이름>.onnx
   └─ 메피스토런\ …
```

- **프로젝트 안 폴더 이름은 대문자로 시작한다**(사용자, 2026-09-15 - `Images`·`Labels`·`Captures`·`Recordings`·`Resources`, 이름은 `ProjectPaths.*Folder`). `bin` 만 VS 관례대로 소문자.
  옛 소문자 폴더는 솔루션 탭이 프로젝트를 고를 때 이름을 맞춘다(`ProjectPaths.NormalizeFolderCase`). Windows 는 대소문자를 안 가려 안 맞춰도 열린다.
  **YOLO 학습 함정**: Ultralytics 는 경로를 `resolve()` 로 실제 이름(`Images`)으로 푼 뒤 `\images\` 를 대소문자 가려 `\labels\` 로 바꿔 라벨을 찾는다 -
  그대로면 라벨을 한 장도 못 찾는다. `도구\yolo-학습.py` 의 `allow_capital_folders` 가 대소문자 안 가리게 바꿔 끼운다.

- **프로젝트 폴더가 곧 데이터셋 폴더다.** 학습·재현율·모델 들이기 코드는 보는 자리만 이것이다.
- 데이터(사진·라벨·모델·영역)는 **폴더 규약**으로 두고 `.mtsproj` 목록에 **안 넣는다** - 사진 수백 장이 들어가면 솔루션 탐색기를 못 쓴다. 탐색기는 `bin`·`obj` 를 안 본다.
  폴더 감시도 데이터를 목록에 안 넣는다(`ScriptProjectWorkspace.IsIgnored` - `Images`·`Labels`·`Captures`·`Recordings` 폴더, 바로 아래 `classes.txt`·`class-colors.json`·`data.yaml`·`coco.json`·`labels.cache`·`regions.json`·`settings.form.json`·`settings.values.json`·`detector.*`·`*.bak`).
  예전 감시가 넣어 둔 것은 프로젝트를 열 때 목록에서만 뺀다(`PruneDataItems`, 파일은 그대로). 검사 `--solution`.
- 완성품을 프로젝트 폴더의 `bin` 에 두는 이유: 모델·영역·리소스가 이미 그 폴더에 있어 따로 복사할 것이 없다. 플레이는 `bin` 의 위 폴더에서 모델·영역을 읽는다.
- 학습 경로(`Vision.TrainingRoot`, 파이썬 환경)는 바깥에 한 벌이다.

## 솔루션 파일 (.mtsln)

```json
{
  "version": 1,
  "name": "디아2",
  "startupProject": "안달리엘런/안달리엘런.mtsproj",
  "projects": [
    { "path": "공용/공용.mtsproj",             "kind": "Shared" },
    { "path": "안달리엘런/안달리엘런.mtsproj", "kind": "Normal" }
  ]
}
```

- 경로는 **솔루션 폴더 기준 상대, `/`** - 폴더째 옮겨도 열린다. 솔루션 폴더 밖 프로젝트는 못 넣는다.
- `.sln` 과 같이 **목록만 든다** - 폴더에 만들어 놓기만 해서는 안 들어간다. 없어진 프로젝트는 빼지 않고 "찾을 수 없음" 으로 남긴다.
- `kind` 는 **이름으로 저장**(늘리기만). 시작 프로젝트가 없거나 사라졌으면 첫 보통 프로젝트. 공유 프로젝트는 시작 프로젝트가 될 수 없다(`Runnable`).
- 모델 `Solution`·`SolutionWorkspace`(Core, 지금 솔루션·시작 프로젝트·최근 목록 `Project.RecentSolutions`·`Changed` 이벤트).

## 프로젝트 (.mtsproj)

`Input/Scripting/Projects/ScriptProject`. 항목 종류(`ScriptItemKind`, 늘리기만): `Source` · `Resource` · `Reference`(DLL) · `ProjectReference`.

- **파일은 프로젝트 폴더 밖을 못 가리킨다** - 폴더째 옮겨도 열리는 성질이 거기서 나온다. 공유는 **프로젝트 참조**(`../공용/공용.mtsproj`)로 한다. 다른 드라이브·자기 자신은 거절.
- `ToUnit` 이 참조의 참조까지 한 번씩(고리 안전) 읽어 **그 프로젝트의 소스(시작 파일 빼고)·DLL 참조를 앞에** 합친다 - 실행·검사·완성·빌드가 다 따라온다.
- 공유 프로젝트는 만든다고 저절로 물리지 않는다(VS 와 같다) - 스크립트 화면 솔루션 탐색기 추가 > `공유 프로젝트 참조`.

## 화면 짜임 - 깊이로 내려간다 (TamsTools StreamMode 와 같다)

```
Minguk Tools
├ 자동화
│  ├ 환경설정        ← 작업공간·학습 경로 (솔루션과 무관 - 여기서 작업공간을 바꿔야 솔루션을 고르므로 솔루션 탭 밖이다)
│  ├ 솔루션          ← 최상위 탭 하나
│  │   위 : 작업공간(보이기만) → [솔루션 ▾] → [프로젝트 ▾] [새 프로젝트][새 공유 프로젝트][새 솔루션]  폴더  [화면닫기]
│  │   아래 : [화면캡처][라벨링][스크립트][설정]   ← 닫기 없음, 위에서 고른 프로젝트를 따라감
│  └ 플레이          ← 돌리는 쪽. 작업공간의 모든 bin 완성품 목록 "오버워치 / 사격장"
└ 입력 테스트        ← 점검 도구
```

- 솔루션 콤보는 최근 목록이 아니라 작업공간 **바로 아래(한 겹)** 의 `.mtsln`(`Solution.FindUnder`). 열기로 밖에서 연 솔루션은 콤보가 비지 않게 같이 넣는다.
- **아래 탭은 진짜 문서다** - 안쪽 `DocumentGroup` + **이름 붙인** `TabbedDocumentUIService`(`AutomationDocumentManagerService`, 셸에도 같은 서비스가 있어서).
  부모 넣기·닫기·파기를 DevExpress 가 한다(`DXTabControl` 이면 손으로 넘겨야 하고 틀리면 캡처 세션이 게임 창을 붙잡는다).
  **`CacheTabsOnSelecting`** - `CacheAllTabs` 는 여는 순간 세 화면이 다 초기화됐다. 안 연 탭의 `SaveSettings` 는 바탕이 건너뛴다.
- 솔루션 탭이 닫히면 아래 문서를 전부 `Close()`(`DestroyOnClose`). 앱 종료 때는 이 탭의 `SaveSettings` 가 아래 화면에 `SaveSettingsNow` 를 넘긴다. 탭 활성화도 아래로 넘긴다(전역 단축키).
- **프로젝트·솔루션을 바꾸면 아래 화면을 닫고 다시 연다** - 화면들이 자리를 열 때 읽고 들고 있어서다. 닫기를 막는 화면이 있으면 바꾸지 않고 콤보를 되돌린다.
  그래서 한 번에 보는 프로젝트는 하나고, 설정 키에 프로젝트를 섞을 일이 없다.
- **새 프로젝트·새 솔루션은 이름을 먼저 묻고 만든 뒤에 넘어간다** - 아래 화면을 먼저 닫으면 취소했을 때 캡처만 끊긴다.
  새 프로젝트 = `NameInputWindow`(같은 이름 폴더면 창 안에서 막음) → `.mtsproj`·`main.csx`·`Images\`·`Labels\` → 솔루션에 넣고 시작 프로젝트로. 새 솔루션 = 시작 창의 만들기 칸.
  만든 뒤 닫기를 막는 화면이 있으면 넘어가지 않는다(새 솔루션이면 앞 솔루션으로 되돌린다).
- 솔루션 탭과 옛 최상위 화면 탭은 배치 복원에서 되살리지 않는다(`OldDocumentNames`) - 되살리면 시작 창을 안 거친다.

## 시작 창

솔루션 메뉴를 누를 때 솔루션이 없으면 뜬다(`SolutionGate.EnsureOpen`, 메뉴 항목의 `REQUIRES_SOLUTION`). 그만두면 그 화면만 안 열린다. VS 2026 시작 창 모양.

- 최근 목록(최신 우선 10개), 없는 폴더는 흐리게 두고 누르면 지울지 묻는다. 새로 만들면 솔루션과 첫 프로젝트를 같이 만든다(빈 솔루션은 아무것도 못 한다).
- 옛 자리에 데이터가 남아 있으면 먼저 옮길지 묻는다(`SolutionMigration`, `--migrate [--apply]`). 무엇을 어디로 옮기는지 보여 주고 묻는다. junction 폴더(`몹-yolo`)는 옮기지 않는다.
- 창 닫기는 `ICurrentWindowService`(진짜 창에서는 `ICurrentDialogService` 가 null). 최근 목록 더블 클릭은 `TableView.RowDoubleClick`(셀 템플릿이 `MouseDoubleClick` 을 먹는다).

## 셸 - 창 제목

- **창 제목** `Minguk Tools v1.0.0`(`MainWindowViewModel.Title`). 솔루션·프로젝트 이름을 넣었다가 뺐다(사용자, 2026-09-15) - 솔루션 탭 제목도 `솔루션` 그대로(아이콘은 메뉴와 같은 tree.png).
- 제목 표시줄의 **`▶ <시작 프로젝트>` · `중지` 버튼은 뺐다**(사용자, 2026-09-15). 돌리기는 플레이 화면, 빌드는 스크립트 화면.
  `PlayViewModel.FindStartupBuild`(시작 프로젝트의 `bin\<이름>.mtsx`, 없으면 bin 의 최근 것)는 `--solution` 검사가 보고 남아 있다. `RequestRun`·`RequestStop` 은 부르는 곳이 없어졌다.
- **시작 프로젝트 고르는 곳은 솔루션 탭 위 칸 하나다** - 다른 데서도 바꾸면 솔루션 탭 아래 화면이 옛 프로젝트를 들고 있어 어긋난다.
- **F5·F6·Pause 는 화면들이 쥔다**(`HotkeyClaim` - 마지막에 본 화면이 받는다). 스크립트 화면 F5 는 편집 중인 글, 플레이 F5 는 완성품이다. 동시에 두 런이 돌지 않게 하는 것은 사람의 몫이다.

## 스크립트 화면의 솔루션 탐색기

- 열린 프로젝트가 지금 솔루션에 들어 있으면 뿌리가 `솔루션 '오버워치' (N개 프로젝트)`(`ScriptNodeKind.Solution`, Id `<솔루션>`).
  그 아래 **열린 프로젝트**(Id `""` - 작업 공간 명령이 모두 이것을 뿌리로 안다, 시작 프로젝트면 굵게)와 **솔루션의 다른 프로젝트들**(Id `<프로젝트>` + .mtsproj 경로, 폴더·파일은 전체 경로 Id, `IsExternal`).
- 다른 프로젝트 파일은 열어 고칠 수 있다. 더하기·지우기·이름 바꾸기는 오른쪽 메뉴 **`이 프로젝트 편집`**(`EditProjectCommand`)으로 그 프로젝트로 넘어가서 한다 - 넘어가면 F5 도 그 프로젝트를 돌린다.
- 참조 줄(`이름 (공유)`)은 삭제가 아니라 제외(참조 빼기)만. 참조한 프로젝트가 솔루션에 있으면 참조 줄 아래에 파일을 또 달지 않는다. 솔루션 밖에서 연 프로젝트는 프로젝트가 뿌리고 참조 줄 아래 공유 소스가 달린다.
- 공유 파일에도 완성이 붙는다(`UnitFor` 가 열린 프로젝트의 한 벌 Sources 로 가린다). 폴더 감시는 폴더 밖 참조를 없어졌다고 빼지 않는다.

## 검증

- `--solution` - 솔루션 만들기·왕복·시작 프로젝트·폴더 밖 거절·화면들이 프로젝트를 따라가는지·작업공간 아래 찾기·공유 프로젝트(참조 전 빌드 실패 → 참조 뒤 성공, 고리, 탐색기 잠금)·
  솔루션 뿌리 탐색기·`이 프로젝트 편집`·▶ 완성품 찾기. 사용자 최근 목록은 안 건드린다(`SolutionWorkspace.Use(…, remember: false)`).
- `--views` · `--script-screen` · `--labeling-screen` - 화면 생성·바인딩. 창(MainWindow)은 하네스가 안 만든다 - 제목 표시줄을 고치면 앱을 띄워 본다.

# 자리 안에 칸을 두고 칸마다 읽는다

2026-09-16 · 설계

## 왜

오버워치 탄약 「17 | 24」 의 구분선(폭 1px 청록 실선)을 인식 모델이 빈칸이나 `1` 로 읽는다. 엔진에 자동 구분선
찾기(`SeparatorSplit`)를 넣어 탄약 숫자 18 → 30/39 로 올렸지만, 사람이 **확실하게** 나눌 길도 필요하다.

사용자 구상(2026-09-16):

> 그룹용 AdornerLayer 를 놓고 그 위에 Adorner 를 내려놓는 거지. 이미지 분석할 때는 AdornerLayer 기준으로 읽는 거고.
> LayoutControl 에 LayoutGroup 처럼. 기존 Adorner 가 AdornerLayer 가 되는 거고, AdornerLayer 가 선택되어 있으면 Adorner 추가 버튼이 활성화.

자식은 **읽을 칸**이다(사용자 답). 스크립트는 **자리 이름 + 칸 이름**으로 부른다(사용자 답).

### 안 고른 길 (실측, 같은 39장)

- 자리 안 고정 가로 범위를 **지우고** 한 줄로 읽기 - 13/39 (가운데가 빈칸이 되어 `3640` 으로 붙는다)
- 고정 범위를 **빼고 좌우 따로** - 28/39. 구분선이 무기마다 28열/42열로 움직여 한 범위로 둘 다 못 잡는다.
- 칸은 이것과 다르다 - 칸은 사람이 **읽을 것**을 둘러싸므로 구분선이 칸 밖에 남는다. 무기가 바뀌어 자리가 달라지면 칸을 고치거나 자동 찾기에 맡긴다.

## 칸은 돌릴 수 있다

사용자(2026-09-16): 「Adorner 는 꼭 사각이 아니어도 되게, 대각선 사각」 → **돌린 직사각형**(사용자 답).

- 칸에 `angle`(도, 시계 방향 +)을 둔다. `x, y, width, height` 는 **돌리기 전** 상자(자리 기준 0~1)이고, 상자 가운데를 중심으로 돈다.
- **회전은 픽셀 공간에서** 한다 - 0~1 비율은 가로세로 배율이 달라 비율 공간에서 돌리면 찌그러진다. 화면 픽셀로 바꾼 뒤 돌린다
  (캔버스와 프레임은 같은 비율로 늘어나므로 둘 다 같은 모양이 된다).
- 읽을 때: 돌린 칸을 감싸는 축 상자를 프레임에서 잘라, 역회전 양선형 샘플링으로 **똑바로 세운 상자**(너비×높이 픽셀)를 만들어 엔진에 넣는다.
  WPF `TransformedBitmap` 은 90° 단위만 돌려 못 쓴다. 감싸는 상자를 구하려면 프레임 크기가 필요해 허브에 `TryGetFrameSize` 를 더한다.
- 편집기: 칸 어도너에 위쪽 **회전 손잡이**(참조 `ResizeRotateAdorner` 의 회전 Thumb 을 되살림). 칸 항목은 `RenderTransform` 으로 돈다.
  칸 항목이 돌아 어도너 안 Thumb 의 변위는 **이미 돌린 좌표계**로 온다(구현 중 바로잡음) - 캔버스가 화면 좌표로 돌려 `ResizeRotated`(반대편 변 제자리)에 넣는다.
- 자리는 돌리지 않는다(축 사각형 그대로).

## 이름

화면에는 **자리**(그룹)·**칸**(자식). 코드는 `NamedRegion`(자리) · `RegionCell`(칸).
`AdornerLayer`·`Adorner` 는 WPF 의 `System.Windows.Documents` 형식과 겹쳐 코드 이름으로 안 쓴다.

## 저장 (`regions.json`)

```json
{ "name": "탄약", "x": 0.92, "y": 0.87, "width": 0.043, "height": 0.049, "live": true, "note": "",
  "cells": [ { "name": "현재", "x": 0.0, "y": 0.0, "width": 0.4, "height": 1.0 },
             { "name": "최대", "x": 0.6, "y": 0.0, "width": 0.4, "height": 1.0 } ] }
```

- 칸 좌표는 **자리 기준 0~1**. 자리를 옮기거나 늘리면 칸이 따라간다.
- **자리에는 칸이 늘 하나 이상**. 새 자리를 만들면 자리와 같은 크기의 「칸1」. 마지막 칸은 못 지운다.
- **옛 파일**(`cells` 없음)은 읽을 때 「칸1」 을 붙인다 - 지금과 똑같이 읽힌다. 다음 저장에서 `cells` 가 적힌다.
- 이름에 `.` 을 못 쓴다(스크립트 `자리.칸` 표기). 칸 이름은 **그 자리 안에서** 겹치지 않는다.

## 읽기와 스크립트

- 읽는 것은 **칸들뿐**. 자리의 나머지는 읽지 않는다. 칸 안에서도 엔진의 자동 구분선 찾기는 그대로 돈다.
- 자리를 부르면 **칸 순서**(목록 순서)대로 읽어 잇는다 - 글은 띄어쓰기로, 숫자는 덩어리를 차례로.

| 부르기 | 결과 |
|---|---|
| `읽기("탄약")` | 칸들의 글을 띄어쓰기로 이음 |
| `읽기("탄약.현재")` | 그 칸만 |
| `숫자들읽기("탄약")` | `[17, 24]` |
| `숫자읽기("탄약.최대")` | `24` |
| `숫자읽기("탄약", 1)` · `글자있나("탄약")` | 같은 규칙 |

- 기존 스크립트(`읽기("탄약")`)는 칸이 하나라 그대로 돈다. 이름은 대소문자를 안 가린다(지금과 같다).
- `계속 읽기` 는 자리 단위. `읽은 글자` 는 칸마다 적고, 자리는 이은 것을 적는다.
- `지금 읽기` 는 칸을 골랐으면 그 칸, 자리를 골랐으면 자리 전체.

## 편집기 (미리보기)

- 칸은 `RegionCanvas` 위에 자리 항목(`RegionItem`)과 **별개의 항목** `RegionCellItem` 으로 자리 위에 놓인다.
- 고르면 **별개의 어도너** `RegionCellAdorner`(초록 테두리·손잡이)가 어도너 층에 붙는다. 자리를 고르면 지금의 주황 `RegionResizeAdorner`.
  칸을 고른 동안에는 자리 어도너를 떼어 손잡이가 겹치지 않게 한다(자리는 선택 상태로 남는다).
- **칸을 누르면 칸 선택**, **칸 밖의 자리 안쪽을 누르면 자리 선택**. 칸을 끌면 칸만 움직이고 **자리 밖으로 못 나간다**. 자리를 끌면 칸이 같이 움직인다.
- 칸 끌기 계산은 자리 끌기와 같은 `RegionGeometry.Move`·`Resize` 를 **자리 사각형을 그림 자리(area)로 넣어** 쓴다. 결과는 `CellEdit` 로 VM 에 올린다.
- 편집 중이 아닐 때 겹그림(`DetectionOverlay`)은 자리 테두리 안에 칸을 점선으로 그린다.

## 영역 패널

- 그리드는 `GridControl` + **`TreeListView`**(`TreeDerivationMode="ChildNodesSelector"`, 자리 → 칸). 열: `이름 · 계속 읽기(자리 줄만) · 읽은 글자`.
- 도구 줄: `새 자리 · 칸 추가 · 지금 읽기 · 지우기 · 영역 보기`. **`칸 추가` 는 자리(또는 그 칸)를 골랐을 때만** 켜진다.
  누르면 자리 가운데에 폭 50%·높이 100% 칸이 생기고 이름 칸이 편집 상태가 된다. 오른쪽 버튼 메뉴도 같다.
- `지우기` 는 칸을 골랐으면 칸(마지막 칸이면 거절하고 알림), 자리를 골랐으면 자리.

## 검사

- `--vision`: 저장·되읽기 · 옛 파일에 「칸1」 · `자리.칸` 찾기(대소문자·없는 칸) · `.` 든 이름 거절 · 칸 좌표 ↔ 화면 좌표 · 칸이 자리 밖으로 못 나감 · 칸들 읽은 것 잇기
- `--script-screen`: 트리(자리 → 칸) · 칸을 고르면 칸 어도너만 붙음(자리 어도너는 떨어짐) · 칸 끌기가 VM 까지 · 정렬 · 바인딩 오류 0
- `--views`, `--ocr`, `--ocr-bench`(자동 구분선 찾기와 함께 숫자가 안 떨어지는지)

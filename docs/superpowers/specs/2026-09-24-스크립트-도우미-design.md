# 스크립트 도우미 - 화면을 보고 요청대로 스크립트를 한 줄씩 적는다

사용자(2026-09-24):
- "스크립트 너 처럼 만들어 줄 수 있는거"
- "현재 화면 미리보기로 보여주고 오른쪽 위에 버튼 눌러줘. 이러면 스크립트 내용에 순차 적으로 만들어 주는거야.. 함수도 니가 미리 만들어 둔거 참고 해서"

정한 것(같은 날, 질문에 답):

| 물음 | 답 |
|---|---|
| 모델이 찾은 자리 | **미리보기에 영역으로 띄워 확인한 뒤 넣는다** - 사람이 손잡이로 고치거나 그대로 [넣기] |
| 누르는 코드 | **그림누르기 + 본보기 자동 저장** - 버튼이 안 떠 있으면 안 누르고, 조금 움직여도 찾는다 |
| 코드 만드는 법 | **동작 조립 + 필요할 때만 자유 코드** - 모델은 동작과 값만 고르고 코드는 프로그램이 적는다 |

## 왜 이렇게 나누나

Claude 가 스크립트를 짤 때 하는 일은 넷이다: 화면을 본다 → 자리를 잡는다 → 영역·본보기를 만든다 → 코드를 적고 컴파일로 확인한다.
작은 로컬 모델(이 PC: qwen2.5vl:3b, qwen3:8b 대부분 CPU)은 이 넷을 한 번에 맡기면 틀린다(실측 2026-09-24: 같은 화면에서 지역·레벨·적 유무를 묻는 방식마다 다르게 답했다).
그래서 **모델에는 "무슨 동작을, 어디에" 만 묻고**, 영역·본보기·코드는 이미 있는 기능(`AddRegion`·영역 이미지 저장·스크립트 API)이 만든다.
자리는 틀리기 쉬우니 사람이 미리보기에서 확인한다.

## 흐름

1. 스크립트 화면의 **「AI 도우미」 패널**(도킹, 아래 탭 줄 - 영역·출력 옆)에 요청을 적는다: "오른쪽 위 설정 버튼 눌러줘".
2. [보내기](Enter) → 지금 미리보기 프레임을 긴 변 1024px 로 줄여 그림 모델(`llm.json` 의 visionModel)에 보낸다.
3. 모델은 **동작 계획(JSON)** 으로 답한다 - 스키마로 묶어 목록 밖 동작은 못 낸다.
4. 계획을 보여 준다: 무엇을 하려는지 한 줄 + 들어갈 코드.
   누르기처럼 자리가 필요한 동작이면 **새 영역을 만들어 미리보기에 띄우고 고른다**(영역 보기 켬). 사람이 손잡이로 맞춘다.
5. [넣기] → 자리가 있으면 그 영역을 **본보기(Resources\이름.png)로 저장**하고, 코드를 편집기 **커서 줄 다음**에 넣는다(되돌리기 된다).
   [버리기] → 만든 영역을 지운다.
6. 넣을 때마다 한 줄씩 늘어 스크립트가 **순서대로** 쌓인다. 다음 요청을 적는다.

## 동작 계획(모델 답)

```json
{ "action": "누르기", "name": "설정버튼", "box": [1180, 20, 1230, 60], "key": "", "ms": 0, "text": "", "code": "", "say": "오른쪽 위 톱니 모양 설정 버튼을 누른다" }
```

| action | 쓰는 값 | 적는 코드 |
|---|---|---|
| 누르기 | name, box | `그림누르기("설정버튼.png");` + 영역·본보기 |
| 나타날때까지 | name, box, ms | `for (var 번 = 0; 번 < 50 && !그림있나("설정버튼.png"); 번++) 쉬기(100);` (ms 5000 이면 50번) + 영역·본보기 |
| 키 | key | `키("F");` |
| 쉬기 | ms | `쉬기(1000);` |
| 글입력 | text | `줄입력("…");` |
| 코드 | code | 모델이 쓴 C# 그대로 - **컴파일 검사**, 오류가 나면 오류를 보여 주고 글 모델(textModel)에 한 번 고치게 한다 |

- **box 는 모델에 보낸 그림의 픽셀**(Qwen2.5-VL 은 절대 좌표로 상자를 낸다). 보낸 크기로 나눠 0~1 로 바꾼다.
  Qwen3-VL 처럼 0~1000 비율로 내는 모델도 있어 `llm.json` 의 `boxUnits`(`pixel` | `1000`)로 고른다 - 모델을 바꾸면 이것도 본다.
- 함수 목록은 **이름·인자만** 넣는다(설명까지 넣으면 수천 토큰이라 이 PC 에서 30초 넘게 더 걸린다).
- **name** 은 영역·본보기 이름 - 점(.)·빈 이름은 고치고(`RegionBook.IsValidName`), 겹치면 뒤에 번호를 붙인다.
- 모델 프롬프트에는 **이미 있는 영역 이름**과 **스크립트 API 목록(한글 이름·설명, `ScriptApiCatalog`)**, **지금 스크립트 끝 몇 줄**을 넣는다 -
  "니가 미리 만들어 둔 함수 참고" 를 모델도 한다. `코드` 동작에서 없는 함수를 지어내지 않게.

## 나누는 곳

| 곳 | 무엇 |
|---|---|
| `Llm/ScriptAssistant.cs` | 순수 - 요청 만들기(스키마·프롬프트), 답 읽기(`AssistantPlan`), 코드 적기(`Render`), 상자 → 0~1, 이름 다듬기. 검사가 가짜 답으로 본다 |
| `ViewModels/ScriptStudioViewModel.Assistant.cs` | 화면 - 프레임 얻기, 모델 부르기(배경), 영역 만들기·지우기, 본보기 저장, 편집기에 넣기, 컴파일 검사 |
| `ScriptStudioView.xaml` | 「AI 도우미」 LayoutPanel - 요청 칸 + [보내기] · 계획 한 줄 · 코드 미리보기 · [넣기][버리기] · 상태(모델·시간) |

## 하지 않는 것

- 여러 줄 계획을 한 번에 세우기 - 한 요청에 한 동작. "순차적으로" 는 사람이 요청을 이어 적는 것으로.
- 스크립트를 돌려 보며 스스로 고치기 - 입력이 게임으로 나간다. 사람이 F5 로 돌려 본다.
- 파이썬·자바스크립트 - C#(기본 언어)만. 다른 언어 문서면 [넣기]를 막고 말한다.

## 검사

- `--vision`: `ScriptAssistant` - 스키마 모양, 답 읽기(상자·이름·목록 밖 동작 거절), 동작마다 적는 코드, 상자 0~1 바꾸기, 이름 겹침.
- `--llm --image=<화면>`: 진짜 그림 모델로 "오른쪽 위 버튼 눌러줘" 계획을 받아 상자를 그린 PNG 를 남긴다(사람이 눈으로 본다).
- `--views`·`--script-screen`: 새 패널이 뜨고 바인딩 오류·정렬이 없는지.

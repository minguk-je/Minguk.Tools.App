# 미니맵으로 방향을 보고 움직인다

2026-09-23 · 설계

## 왜

사용자(2026-09-23): 「게임내에 던전 미니 맵이 있는데 캐릭터 방향도 있고 이동키와 마우스 회전은 시점 방향이고
미니맵으로 방향 보면서 처리가 가능해?」

게임에 자동 이동이 있지만 **「자동 이동할 수 없는 퀘스트입니다」** 가 뜨는 곳이 있다(던전, 실제 화면). 그때는
스스로 방향을 잡아 걸어야 한다. 검출·OCR·본보기 대조는 「화면 어디에 무엇이 있나」를 답하지 지금 **어느 쪽을
보고 있나**는 답하지 못한다. 미니맵 화살표가 그 답을 들고 있다.

## 실측 - 스크린샷 다섯 장으로 확인한 것

같은 게임의 필드 1장 + 던전 4장(요새의 무덤 1, 요새 감옥 3). 던전 셋 중 하나는 **마우스만 돌린 뒤**, 하나는
**걸은 뒤**다.

| 확인 | 결과 |
|---|---|
| 미니맵·화살표 자리 | 필드·던전 **같다**(화면 1772, 181 중심, 1920x1080) |
| 색 분리 | `밝기 > 175 && R − B < 12` 하나로 61~71px, 잡음 1px 이하. 노란 원·흰 길 띠 위에서도 깨끗 |
| 지도 방향 | 필드·던전 둘 다 **북쪽 고정**(화살표가 돈다) |
| 화살표가 가리키는 것 | **캐릭터 몸**. 걸으면 돌고(56°), 마우스만 돌리면 **안 돈다**(0°, 겹침 0.97) |
| 각도 정밀도 | **±1~2°**. 서로 다른 기준 셋으로 재도 303·304·304° |
| 목표 마커 | 노란 ▼ 를 12px 이상 뭉치로 분리, 방위·거리가 나온다. 걸으니 105 → 118px 로 멀어짐(맞는 방향) |

### 안 고른 길

- **무게중심·끝점 방향으로 각도** - 필드 한 장에서는 63.6°/65.6° 로 맞는 듯했으나 **던전에서 깨졌다**.
  이 아이콘은 **꼬리가 머리보다 길어서** 중심에서 가장 먼 픽셀이 꼬리다. 회전 템플릿 매칭으로 간다.
- **밝은 부채꼴을 카메라 방향으로** - 마우스를 돌리면 부채꼴이 바뀌길래 후보였으나, 한 장에서 **둘로 갈라졌고**
  각각 지도의 통로와 정렬돼 있었다. 시야 콘이 아니다. **미니맵으로 카메라 방향은 못 읽는다.**
- **자동 이동에 맡기기** - 안 되는 퀘스트가 있다(위).
- **던전 통로 경로 계획** - 벽 인식이 따로 필요하다. 방위만으로 대부분 된다. 필요해지면 그때.

### 카메라를 못 읽어도 되는 이유

알고 싶은 것은 카메라 각도가 아니라 **「W 를 누르면 어디로 가나」**다. W 를 누르면 캐릭터가 카메라 정면으로 걷고
그때 **몸이 그쪽으로 돈다**. 걷는 동안의 몸 방향이 곧 이동 방향이다. 화살표가 몸 방향인 것이 오히려 맞다.

되먹임: `걷기 → 방위 읽기 → 목표와의 차이만큼 마우스 회전 → 되풀이`. 목표는 가만히 있고 방위는 ±2° 로
읽히니 조준보다 훨씬 쉬운 문제다 - 회전 배율이 틀려도 수렴한다.

## 익히기 - 버튼 하나

머리를 **모양만으로** 가린다. 머리는 **짧지만 넓고**(삼각형) 꼬리는 **길지만 가늘다** - 그래서 방향마다 부챗살(±35°)
안 픽셀의 **중심거리 합**을 재면 머리가 이긴다(실측 머리 87~94, 꼬리 67~77).

| 장면 | 자동 판별 | 눈으로 잰 값 |
|---|---|---|
| 필드 | 52° | 55° |
| 던전 | 94° | 90° |
| 걸은 뒤 | **55°** | **35°** ← 틀림 |

**갈래를 봉우리로 뽑아 순위를 매기는 방법은 버렸다.** 꼬리 끝 1~2px 이 색 문턱을 넘나드는 것만으로 갈래 길이가
11.6 → 8.6 으로 바뀌어 순위가 뒤집혔고 머리를 148°·265° 로 골랐다(구현 중 검사가 잡음). 거리 **합**은 갈래 전체를
보므로 픽셀 한둘에 흔들리지 않는다. 그래도 **걸은 뒤 장면은 20° 틀린다** - 그 장면은 머리와 꼬리의 무게 차가
1.05배뿐이라(다른 둘은 1.13·1.18배) 어느 쪽이 머리인지 모양만으로는 정해지지 않는다.

그래서 **여유 배수(`HeadMargin`)를 같이 준다**:

1. 이름 붙인 자리 `미니맵` 가운데 `box`×`box` 를 자른다
2. 색으로 고르고 **2px 틈까지 이어** 가장 큰 뭉치만 남긴다 - 꼬리 끝이 안티앨리어싱으로 흐려져 여덟 이웃만으로는
   떨어져 나간다(71px 이 68+2+1 로)
3. 무게중심 = 화살표 중심, 부챗살 거리합 최대 = 기준각, 여유 = 그 무게 ÷ 60° 넘게 떨어진 곳의 최대 무게
4. 조각 원본을 `Resources/미니맵화살표.png`, 나머지를 `minimap.json` 에 저장하고 **한국어로 알린다** -
   여유가 1.1 미만이면 「뚜렷하지 않습니다, `출력(방위())` 을 찍어 보고 다르면 `headingAtTemplate` 을 고치세요」

조각 원본을 저장하므로 색 규칙을 바꿔 다시 뽑을 수 있고, 사람이 파일을 열어 눈으로 확인할 수 있다.

## 읽는 방법

**방위** - 같은 자리·같은 규칙으로 마스크를 만들고, 본보기를 1°씩 360번 돌려 겹침(IoU)이 가장 큰 각 θ.
방위 = `(기준각 + θ) % 360`. 두 마스크 모두 **제 무게중심**을 회전 중심으로 놓는다(실측에서 이 정렬로 1° 일치).
65픽셀 × 360각 ≈ 2만 번이라 **매 프레임 돌려도 무시할 수준**이다 - 사인·코사인은 각도마다 한 번만 센다.

**목표 마커** - 미니맵 전체에서 노랑 규칙으로 뭉치를 모아 12px 이상만, 화살표 중심 기준 방위와 거리(px). 가까운 순.

## 회전 배율 - 걷기를 끼워 잰다

마우스를 돌려도 화살표는 안 도니 「N 카운트 → 몇 도」를 바로 못 잰다. 한 단계 길어진다:

```
방위 읽기 → 마우스 가로 N 카운트 → W 짧게(0.3초) → 방위 다시 읽기
도당카운트 = N ÷ 방위차
```

벽에 막히면 몸이 안 돌아 방위차가 0 근처가 된다 - 그런 표본은 버린다. 조준 배율과 같이 **여러 번 재서 가운뎃값**.
배운 값은 `minimap.json` 에 적는다(드물게 일어나므로 파일 쓰기가 부담이 아니다).

## API

이름은 영문·한글 둘 다. 실시간 모드(`ScriptApiMode.Live`)라 표(`ScriptApiCatalog.LiveNames`)에 넣으면
JS·파이썬에 자동으로 심어진다 - `JavaScriptEngine.Bind` 는 계획 모드 전용이라 안 고친다.

| 이름 | 하는 일 |
|---|---|
| `Heading` / `방위` | 캐릭터 몸 방위 0~360(북 0, 시계 방향). 못 읽으면 멈추고 이유를 말한다 |
| `TargetBearing` / `목표방위` | 가장 가까운 미니맵 마커까지 방위·거리(px)·돌 각. 없으면 null |
| `TargetBearings` / `목표방위들` | 마커를 모두, 가까운 것부터 |
| `BearingTo` / `방위차` | 지금 방위에서 그 방위까지 −180~180 |
| `Face` / `바라보기` | 그 방위를 보도록 마우스 가로 회전. **열린 고리**(몸은 안 도니 확인 못 함) |
| `GoTo` / `가기` | 그 방위로 걸어간다 - 걷는 동안 미니맵을 보며 보정 |
| `GoToTarget` / `목표로가기` | 미니맵 마커 쪽으로 간다 |
| `TurnScale` / `회전배율` | 도당 카운트. 없으면 그 자리에서 재서 저장 |

`가기` 가 실제로 쓸 함수다. `바라보기` 는 열린 고리라 정확도가 배율에 달렸다 - 문서에 적는다.

## 둘 곳

```
Minguk.Tools/Vision/Minimap/
  MinimapSpec.cs      ← minimap.json (색 규칙·기준각·자리 이름·도당카운트). HealthBarSpec 과 같은 꼴
  MinimapReader.cs    ← BGRA 바이트를 받는 순수 계산 (익히기·방위·마커). HealthBarReader 와 같은 꼴
Minguk.Tools/Input/Scripting/Live/LiveScriptApi.Minimap.cs   ← API (LiveScriptApi 를 partial 로)
```

`Vision/HealthBars` 가 이미 「프로젝트 폴더 json + 순수 계산기」 꼴이라 그대로 따른다. 외부·하드웨어와 닿지
않으므로 어댑터는 두지 않는다.

익히기 단추는 영역 패널 도구 줄의 `[영역 이미지 저장]` 옆(`RecognizingCaptureViewModelBase.Regions.cs` 의
`SaveTemplateCommand` 이웃) - 스크립트·플레이 화면이 함께 쓴다.

## 검사

**받은 스크린샷 다섯 장을 그대로 회귀 데이터로 쓴다**(`Minguk.Tools.Tests/MinimapData/`). 절대 방위의 정답은
모르지만 **관계가 고정**이라 좋은 정답지다:

- 던전 셋(2·3·4번)은 서로 **0°**(그중 4번은 마우스만 돌린 것 - 0° 가 나와야 한다)
- 걸은 뒤(5번)는 던전 셋 대비 **−56°**(±3)
- 필드(1번)는 던전 대비 **−31°**(±3)
- 목표 마커: 4번 237°·105px, 5번 234°·118px (±3°, ±5px)
- 자동 머리 판별: 여유가 1.1배 이상인 장면(필드·던전)은 ±10, 걸은 뒤(1.05배)는 **못 믿는다는 것을 검사로 못 박는다**

여기에 본보기를 알려진 각도로 돌려 넣는 합성 검사(±4° - 마스크를 돌리면 반올림으로 픽셀이 겹쳐 사라져 모양이 성겨진다)를 더한다. 화면을 안 띄우므로 `--vision` 에 붙이고, 고칠 때 빨리 되풀이하도록 `--minimap`(1초)으로도 뺀다.

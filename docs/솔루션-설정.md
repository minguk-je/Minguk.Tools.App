# 솔루션 설정 — 사용자가 만드는 설정 화면

게임(솔루션)마다 **사람이 컨트롤을 놓아 설정 화면을 만들고**, 스크립트가 그 값을 읽고 쓴다.
"물약 먹을 HP", "자동 줍기", "사냥할 몹 목록" 같이 스크립트를 고치지 않고 바꾸고 싶은 값을 담는다.
(사용자, 2026-09-16 - 정한 것과 이유를 적는다. 만들면서 이 문서를 지금 모양으로 고친다.)

## 정한 것 (사용자, 2026-09-16)

| 물음 | 정한 것 |
|---|---|
| 단위 | **솔루션 공통 + 프로젝트별 덧붙이기** |
| 값 저장 자리 | **솔루션·프로젝트 폴더** (폴더째 옮기면 값도 따라간다) |
| 값 바꾸는 화면 | **설정 탭 미리보기 한 곳** (플레이·스크립트 화면에는 패널을 안 둔다) |
| 처음 컨트롤 | 글자 · 숫자 · 체크 · 콤보 · 슬라이더 · 구역(그룹) · **목록(GridControl)** |

## 파일

```
디아2\
├─ 디아2.mtsln
├─ settings.form.json        ← 솔루션 공통 양식 (어떤 칸이 어디에)
├─ settings.values.json      ← 솔루션 공통 값
└─ 안달리엘런\
   ├─ 안달리엘런.mtsproj
   ├─ settings.form.json     ← 이 런에만 있는 칸 (없어도 된다)
   ├─ settings.values.json   ← 이 런에서 덮어쓴 값 (공통 칸의 값도 여기서 덮는다)
   └─ bin\안달리엘런.mtsx     ← 플레이는 bin 의 위(프로젝트)·그 위(솔루션)에서 읽는다
```

- **양식과 값을 나눈다** - 양식은 만드는 사람이, 값은 쓰는 사람이 고친다. 한 파일이면 값을 바꿀 때마다 양식 파일이 바뀌어 비교(diff)가 더러워진다.
- 둘 다 UTF-8(BOM 없이), 들여 쓴 JSON. 이름은 `SolutionSettingsFiles.FormFile`·`ValuesFile`.
- 데이터 규약과 같이 **`.mtsproj` 목록·솔루션 탐색기에 안 넣는다**(`ScriptProjectWorkspace.IsIgnored`).
- 솔루션 폴더는 프로젝트 폴더의 **바로 위에 `.mtsln` 이 있으면** 그것이다. 없으면(솔루션 밖에서 연 프로젝트) 프로젝트 층만 있다.

### settings.form.json

```json
{
  "version": 1,
  "root": {
    "kind": "Group", "name": "", "orientation": "Vertical",
    "children": [
      { "kind": "Group", "name": "물약", "label": "물약", "orientation": "Vertical", "children": [
        { "kind": "Number", "name": "물약HP", "label": "먹을 HP(%)", "default": 40, "min": 0, "max": 100, "decimals": 0 },
        { "kind": "Check",  "name": "자동줍기", "label": "자동 줍기", "default": true }
      ]},
      { "kind": "Combo",  "name": "난이도", "label": "난이도", "items": ["보통", "악몽", "지옥"], "default": "지옥" },
      { "kind": "Slider", "name": "속도", "label": "속도", "min": 1, "max": 10, "default": 5 },
      { "kind": "List",   "name": "물약목록", "label": "물약 목록", "columns": [
        { "name": "키", "kind": "Text" }, { "name": "HP", "kind": "Number" }, { "name": "켜기", "kind": "Check" }
      ]}
    ]
  }
}
```

- **배치는 우리 트리로 적는다**(`SettingsItem` 의 `children`). DevExpress `LayoutControl` 의 XML 을 그대로 두지 않는다 - DevExpress 를 올리면 못 읽을 수 있고,
  사람이 읽고 고칠 수 없고, 칸과 배치가 두 곳에 나뉘어 어긋난다. 화면은 트리에서 `LayoutControl` 을 짓고, 디자인에서 끌어 옮긴 결과를 트리로 되읽는다.
- `kind`(`SettingsItemKind`)는 **이름으로 저장·늘리기만**: `Group` · `Text` · `Number` · `Check` · `Combo` · `Slider` · `List`.
- `Group` 은 값이 없다(`name` 은 비어도 된다). `orientation` 은 `Vertical`·`Horizontal`, `view` 는 `GroupBox`(기본)·`Tabs`.
- 공통 속성: `name`(스크립트가 부르는 키) · `label` · `tooltip` · `default`. 숫자·슬라이더: `min`·`max`·`step`·`decimals`. 콤보: `items`. 목록: `columns`(`Text`·`Number`·`Check`·`Combo`).
- `name` 은 비지 않고 공백·`.` 이 없다. 양식 안에서 겹치지 않는다(대소문자 가림 - 스크립트 키와 같다).

### settings.values.json

```json
{ "version": 1, "values": { "물약HP": 35, "물약목록": [ { "키": "1", "HP": 30, "켜기": true } ] } }
```

- 양식에 없는 이름의 값은 **지우지 않고 둔다** - 칸을 잠깐 지웠다 되살리면 값이 돌아온다. 설정 탭 도구 모음 `안 쓰는 값 정리` 로만 지운다.
- 형식이 안 맞는 값(숫자 칸에 글자)은 읽을 때 기본값으로 보고, 설정 탭 그 칸에 경고를 띄운다. 파일은 사람이 저장할 때까지 안 고친다.

## 값을 찾는 순서

```
프로젝트 values  →  솔루션 values  →  정의의 default
```

- **정의(칸)** 는 솔루션 양식 + 프로젝트 양식을 합친 것이다. 프로젝트는 공통 칸의 **값만** 덮는다(정의를 다시 두지 않는다).
- 설정 탭에서 덮어쓴 값은 **굵게**. 되돌리기는 편집 대상 콤보 뒤 `초기값` 이 층째로(묻고) 한다 - 칸마다 붙던 `↺` 는 뺐다(사용자, 2026-09-17 "굳이 없어도").
- 목록은 통째로 덮는다(행 단위로 섞지 않는다) - 섞으면 "왜 이 줄이 있지" 를 찾을 수 없다.

### 이름이 겹치면 (사용자 물음, 2026-09-16)

**이름 하나에 정의는 하나.**

- **만들 때 막는다** - 프로젝트 양식에 솔루션 공통과 같은 이름을 넣으면 속성 창에서 막고
  "솔루션 공통에 이미 있는 이름입니다 - 이 런에서만 값을 바꾸려면 미리보기에서 덮어쓰세요" 라고 말한다.
  솔루션 공통에 넣을 때는 **솔루션의 모든 프로젝트 양식**을 보고 막는다(어느 프로젝트에 있는지 이름을 댄다).
  값을 덮는 길이 이미 있으므로 정의를 두 번 둘 까닭이 없다 - 두 번 두면 종류·범위가 달라질 수 있다.
- **이미 겹쳐 있으면**(파일을 손으로 고쳤거나 솔루션 밖에서 만든 프로젝트를 넣었을 때) **프로젝트 정의가 이긴다** - 지역 변수가 바깥 이름을 가리는 것과 같다.
  설정 탭은 그 칸에 경고를 띄우고, 스크립트는 멈추지 않고 출력 창에 한 번 경고를 남긴다. 실행을 멈추면 파일 하나 때문에 돌던 런이 선다.

## 설정 탭

솔루션 탭 아래 `화면캡처 · 라벨링 · 스크립트 · 설정`(`AutomationScreens`). 고른 프로젝트를 따라간다.

```
[편집 대상: 솔루션 공통 ▾]  [디자인]  [▲][▼][지우기]  [다시 읽기][안 쓰는 값 정리][폴더]
┌ 도구 상자 ┐┌──────── LayoutControl ────────┐┌ 속성(PropertyGrid) ┐
│ 구역       ││ 물약 ─────────────────        ││ 이름: 이름·라벨·종류 │
│ 글자       ││  먹을 HP(%)  [ 40 ▲▼]         ││ 칸 값: 처음 값·범위  │
│ 숫자 …     ││ 물약 목록 (GridControl)         ││                     │
│ [놓기]     │└───────────────────────────────┘└─────────────────────┘
└───────────┘  상태 줄: 한 일·오류(⚠) | 양식 파일 자리
```

- 파일: `SolutionSettingsView`·`SolutionSettingsViewModel`(.Model·.Code) · 판 `Markup/Settings/SettingsFormCanvas` · 속성 `ViewModels/Settings/SettingsItemEditors`.
- **나누기**(`Splitter`, 사용자, 2026-09-17 "LayoutSplitter · 좌우 상하 조정"): 도구 상자 칸. DevExpress v26 LayoutControl 에는 따로 놓는 LayoutSplitter 가 없어(같은 이름은 도킹 쪽)
  미리보기에서 **앞 칸**에 `AllowHorizontalSizing`(가로 구역)·`AllowVerticalSizing`(세로 구역)을 켜고 나누기 자체는 안 그린다(`SettingsFormCanvas.AddChildren`). 디자인에서는 `↔ 나누기` 자리표시로 옮기고 지운다.
  값·이름이 없다(`HasValue` false). 끌어 바꾼 크기는 저장하지 않는다 - 판을 다시 지으면 처음 크기. DockLayoutManager 로 하지 않는다(판은 폼, 도킹은 VS 창 틀용).
- **MVVM**(사용자, 2026-09-17): 화면 모델은 판 컨트롤을 모른다. 칸 모델 트리 `SettingsFieldViewModel`(값·굵게·경고·`Children`)을 `Form`(`SettingsFormState` = 뿌리 + 디자인인가)으로 내놓고,
  판은 `Form`·`SelectedItem`(↔ `SelectedFormItem`)·`DropCommand`(↔ `CanvasDropCommand`, `SettingsDrop`)·`LayoutChangedCommand`(↔ `CanvasLayoutChangedCommand`)를 바인딩으로 받는다.
  값: 판이 칸 모델 `Value` 에 쓰면 화면 모델이 층에 저장, 층이 바뀌면 화면 모델이 `Sync`(되돌려 저장하지 않음) → 판이 `PropertyChanged` 로 편집기를 고친다(치던 칸은 안 덮음).
  디자인: 판이 손을 뗄 때·칸을 놓기 전에 끌어 옮긴 결과를 칸 트리(고치는 양식 그 객체)에 되읽고 `LayoutChangedCommand(바뀜)` - 예전 화면 모델의 `CommitCanvas`(판을 찾아 되읽기)는 없다.
  창 자리·크기는 `WindowBoundsBehavior`(코드 비하인드 없음).
- **디자인**(도구 모음 `디자인` 켬): 판은 **편집 대상 층의 양식만** 그린다(합친 것을 그리면 어느 층 칸인지 헷갈린다). 도구 상자에서 **판으로 끌어 놓거나**, 두 번 누르기·Enter·`놓기`.
  - 끌어 놓기(`SettingsToolboxDragBehavior` → 판의 Preview 끌기 이벤트): 칸 위 반이면 앞, 아래 반이면 뒤(가로 구역 안이면 왼쪽·오른쪽 반), 구역 안쪽이면 그 구역 끝,
    구역 머리·밑 8px 띠는 구역의 앞·뒤, 칸이 없는 자리는 맨 끝(`DropTargetAt`). 끄는 동안 파란 선(앞·뒤)·점선 상자(안)로 자리를 보인다.
    사용자 배치 덮개가 칸을 가려 칸마다 끌기 이벤트를 달 수 없어 판이 자리로 계산한다 - 누르기(`HitItem`)와 같은 방식.
  - 도구 상자 줄의 아이콘은 DevExpress.Images 의 16x16 PNG(`DevExpressGlyph`, 사용자 2026-09-17) - 구역 Panel · 글자 TextBox · 숫자 Number · 체크 CheckBox · 콤보 ComboBox ·
    슬라이더 GaugeStyleLinearHorizontal(TrackBar 그림이 없다) · 목록 Grid. 없는 경로면 null(글자만) - `--settings-screen` 이 7개 모두 읽혔는지 본다.
  - 누르기·Enter·`놓기`: 구역을 골라 두면 그 안에, 칸을 골라 두면 그 뒤에, 아니면 맨 끝. 이름은 `글자1` 처럼 안 겹치게 붙고, 놓은 칸이 골라진다.
  - 옮기기·묶기는 `LayoutControl.IsCustomization`. 손을 뗄 때마다 판이 컨트롤 트리를 되읽어(`ReadBack`) 바뀌었으면 저장한다.
    LayoutControl 이 스스로 만든 이름 없는 묶음은 라벨 없는 구역으로 받고, 빈 묶음은 버린다. ▲▼ 는 같은 구역 안에서 순서만.
  - **고르기는 판이 한다** - 26.1 LayoutControl 은 고른 요소 목록(`SelectedElements`)을 밖에 안 연다. 사용자 배치 덮개가 누름을 먹어 칸의 이벤트도 안 온다.
    그래서 손 뗀 자리에 든 가장 안쪽 칸을 찾고(`HitItem`) 파란 테두리(adorner)를 그린다.
  - 속성 창은 칸 종류마다 다른 객체(`TextEditor`·`NumberEditor`·`ComboEditor`·`ListEditor`·`GroupEditor` …). 방향·탭은 참거짓 칸 - 열거형을 두면 `Vertical` 같은 영어가 뜬다.
    **일반 사용자가 만지는 창이라 VS 속성 창보다 단순하게 둔다**(사용자, 2026-09-17 "VS 처럼 보이면 너무 복잡") - 도구 패널·줄마다 표시 단추·바닥 설명 칸 없음, 설명은 툴팁.
    순서는 사람이 읽는 순서 - `SortMode="NoSort"` + 속성의 `[Display(Order)]`(라벨 → 이름 → 툴팁 → 종류, 처음 값 → 최소 → 최대 → 간격 → 소수 자리, 콤보는 항목 → 처음 값).
    가나다순(`Ascending`)이던 때는 `최대` 가 `최소` 앞에 섰다. 선언 순서만으로는 파생 클래스 속성이 먼저 나와 `Order` 를 적는다.
    `default` 는 화면에서 **처음 값** - 미리보기의 지금 값(예: 77)과 속성 창의 `기본값 40` 이 달라 틀린 값처럼 보였다.
    콤보 항목은 `보통, 악몽, 지옥`, 목록 열은 `키:글자, HP:숫자, 켜기:체크, 모드:콤보(보통|지옥)`. 둘 다 길면 잘려서 `MemoEditSettings`(`ShowIcon="False"` - 켜면 글 대신 아이콘이 뜬다)로
    넓게 펼쳐 고친다. 한 줄에 하나씩 적어도 된다(쉼표·줄바꿈 둘 다 나눈다). 검사 `--settings-screen` 이 목록 열 펼치기를 본다.
  - **목록 처음 행**(사용자, 2026-09-17): 속성 창 `처음 행`(`2행`·`없음`) 의 … → 열대로 만든 표 대화 상자(`SettingsListRowsView`·`SettingsListRowsViewModel`, View 의 `ListRowsDialogService`).
    확인이면 `ListEditor.SetDefaultRows` 가 `default` 에 JSON 배열로 넣는다(빈 표면 뺀다). 값을 안 바꾼 층에서는 미리보기·스크립트가 이 행을 읽는다.
    표는 판의 미리보기와 같은 `SettingsListGrid`(열 → DataTable, 맨 아래 새 행, Delete 로 지우기). 글로는 못 적는다 - 줄 셀은 `CellTemplate` 의 `ButtonEdit`(`IsTextEditable=False`) +
    `DefaultButtonClick` → `EditListRowsCommand`. 속성이 읽기 전용이면 속성 창이 … 를 꺼서 빈 setter 를 둔다.
- **미리보기**(디자인 끔): 솔루션 공통 칸 다음에 프로젝트 칸(둘 다 있으면 `이 프로젝트 (이름)` 구역에 묶는다). **값을 바꾸는 곳은 여기 하나다.**
  편집 대상 층에 쓴다 - 단 프로젝트 칸은 늘 프로젝트 층. 편집 대상 층에서 덮어쓴 값은 라벨이 **굵다**. `초기값`(`ResetValuesCommand` → 물은 뒤 `ResetOverriddenValues`)이 그 층의 덮어쓴 값을 모두 뺀다. 경고가 있는 칸은 라벨 앞 `⚠`, 툴팁에 사연.
  목록은 맨 아래 줄에 새 행, Delete 로 행 지우기, 고칠 때마다 통째로 쓴다.
- **플레이 중 값 창**(사용자, 2026-09-17): 플레이·스크립트 화면 실행 설정 줄 `설정`(여는 코드는 `RecognizingCaptureViewModelBase.Settings`) → 모달 아닌 창(`PlaySettingsView`, 플레이 View 의 `SettingsWindowService`).
  화면 모델은 같은 `SolutionSettingsViewModel` 을 `CreateForPlay(프로젝트 폴더)` 로 - 값만(`IsValuesOnly`, 부모 없이 초기화), 폴더는 완성품의 프로젝트(`RecognitionRoot`, 스크립트 `설정()` 과 같은 자리).
  창이라 게임 옆·다른 모니터에 둔다. 이미 떠 있으면 앞으로, 완성품을 바꾸면 새 프로젝트로 다시 띄우고, 플레이 화면이 닫히면 같이 닫는다. 창 자리·크기를 기억하고(`WindowBounds` - `WindowBoundsBehavior` 가 창과 잇고 화면 모델이 닫힐 때 `ValuesWindowBounds` 로 저장, 화면 밖이면 안 건다), 최대화 단추는 없다(`ControlBoxButtonSet`). 검사 `--settings-screen` 의 `플레이 설정 창:` 줄 · `--play-screen` 의 최대화 단추 줄.
- **양식도 값도 고치면 곧바로 저장한다**(환경설정 화면과 같다) - `저장` 버튼·닫을 때 묻기를 두지 않는다. 이름이 틀리거나 겹치면 저장하지 않고 상태 줄에 `⚠` 이유.
- 스크립트가(다른 스레드에서) 값을 쓰면 층의 `Changed` → `DispatcherService` → 그 칸 편집기만 고친다(글을 치던 칸은 안 덮는다). 양식이 밖에서 바뀌면 미리보기만 다시 짓는다.

## 스크립트 API

| 영문 | 한글 | 하는 일 |
|---|---|---|
| `Setting(name)` | `설정` | 값. 숫자·글·참거짓·목록 그대로. C# 은 `Setting<int>("물약HP")` 도 된다 |
| `SetSetting(name, value)` | `설정저장` | 지금 **프로젝트 층**에 쓴다. 설정 탭에도 바로 보인다 |
| `SettingList(name)` | `설정목록` | 목록 칸의 행들. 행은 `row["HP"]` · `row.Get<int>("HP")` |
| `HasSetting(name)` | `설정있나` | 그 이름의 칸이 있는가 |

- **부를 때마다 앱 안의 한 벌(`SettingsLayer.For` - 폴더마다 하나)에서 읽는다** - 플레이가 도는 중에 설정 탭에서 바꾸면 다음 호출부터 먹는다(영역 `Regions` 와 같은 까닭).
  저장소는 프로젝트 폴더 경로로 한 벌씩 나눠 쓰고, 잠금으로 스크립트 스레드·UI 스레드를 가른다.
- 없는 이름은 멈추고 이유를 말한다(`ScriptGuardException`, "설정 「물약HP」 가 없습니다 - 설정 탭에서 칸을 만드세요"). 형식이 안 맞으면(`Setting<int>` 인데 글) 마찬가지.
- 자리: 소스 실행은 `ScriptUnit.ResourceRoot`(프로젝트 폴더), 완성품은 `.mtsx` 가 든 `bin` 의 위(`SolutionSettings.ForScriptRoot`). 둘 다 `LiveScriptHost.ResourceRoot` 에서 푼다 - 호스트에 칸을 더하지 않았다. 한 파일짜리 스크립트는 "프로젝트로 열어야" 로 멈춘다.
- 쓰기는 파일로 곧바로 안 나가고 묶어서(300ms) 쓰고, 실행이 끝나면(`ReleaseAll`) 남은 것을 쓴다. 파일은 옆에 쓰고 바꿔 끼운다(쓰다 죽어도 앞 파일이 산다).
- 겹침·형식 틀림 경고는 멈추지 않고 출력 창에 한 번(`설정 경고: …`). 파이썬·JS 에는 숫자가 정수면 long, 아니면 double 로 간다.
- 함정(실측): 코드에서 만든 `JsonValue<int>` 에 `GetValue<double>()` 을 부르면 터진다 - 숫자는 `SettingsValue.ToDouble` 로만 읽는다.
  `cond ? (long)d : d` 는 삼항식이 double 로 맞춰 정수가 실수로 나간다 - `(object)` 로 감싼다.

## 아직 안 한 것

- 실행 취소(Ctrl+Z) - 양식을 곧바로 저장하므로 잘못 지운 칸은 파일 기록(git)으로 되살린다.
- 스크립트가 솔루션 층에 쓰는 API(`SetSetting` 은 프로젝트 층만).

## 검증

- `--solution` 의 `솔루션 설정:` 줄 - 양식·값 왕복, 찾는 순서, 겹침(막기·프로젝트가 이김), 완성품 자리에서 찾기, 스크립트 읽기·쓰기가 설정 탭 저장소에 보이는지.
- `--settings-screen [--out=폴더]` - 임시 솔루션에 칸 종류를 모두 놓고 화면 밖에 띄운다: 미리보기 칸 순서, 편집기 → 층, 덮어쓰기 굵게·칸에 단추 없음·초기값,
  다른 스레드 쓰기가 편집기에 보이는지, 목록 행, 바인딩 오류, 세로 정렬, 디자인에서 칸 놓기·속성 고치기 저장·겹치는 이름 막기·누른 자리 고르기·지우기, 끌어 놓을 자리(앞·뒤·안·끝)와 놓은 결과,
  속성 창 목록 열 펼치기·처음 행(… 줄·대화 상자 표 고치기·양식 저장·값 없는 칸이 처음 행을 읽기). PNG 네 장(미리보기·디자인·디자인 목록·처음 행 대화 상자).
  대화 상자는 모달이라 … 를 눌러 띄우는 길은 안 본다 - 화면만 따로 띄우고 확인 뒤 하는 일을 부른다.
  실제 마우스 끌기(`DoDragDrop`)는 커서가 있어야 해서 판의 `Drop(종류, 자리)` 를 부른다.
- `--views` 가 설정 탭 생성을 본다.
